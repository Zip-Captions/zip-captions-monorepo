# Handoff: NFR Design -> Code Generation
**Unit**: external-display (Unit 8, S-20)
**Date**: 2026-10-20 (unattended run; answers pre-approved per `.agent/overnight-pipeline.md` A2, subject to morning review)

## Decisions Made
- Design Q1: one window-scoped `_release(Logger)` on `OverlayWindowController` (cancel ready timer, cancel update timer, `closeWindow(captured id)`, `registry.remove(target)`), per-step `on Object` + `runtimeType`, never throws; `close()` nulls `_windowId` synchronously before its first await; the `changes` watch is controller-lifetime (cancelled only in `dispose()`), not a release step — T11/T4/T16 fire from window-less states; `CaptionOverlayTarget.isVisible` becomes a derived delegation to the controller (the shipped field is deleted).
- Design Q2: `Timer? _readyTimer` starts when the open enters `Opening` (before `createWindow`, so the 10 s bound covers the whole open); cancelled structurally in the single private `_setState(next)` whenever `next is! Opening` (Unit 7 idiom) and defensively in `_release`; a late ready is a no-op by construction (`state is Opening` && matching window id).
- Design Q3: every post-ready window call goes through one private `_windowCall`: code `'-1'` while `Open` → `WindowClosed` (never rethrown into the shell's `unawaited`); any other `PlatformException` → fixed-string warning, ignored (B-5); `createWindow`'s throw is caught in the open sequence itself (T6); a pre-ready `'-1'` is logged and ignored — the ready timeout is the catch-all (BR-U8-04's own scoping + B-5).
- Design Q4: snapshot delivery is a dirty flag plus one re-arming 16 ms timer (`captionUpdateInterval`), not a reset timer — a reset timer starves under a continuous stream; the stored snapshot doubles as the held snapshot sent on ready; `overlayReadyTimeout`/`captionUpdateInterval` are named consts in `overlay_window_controller.dart`, `maxEncodedBytes` a static const on the codec.
- Design Q5: the BR-U8-18 redaction audit is one record-level test (capturing `Logger.root.onRecord` + sentinel caption string) driving the decode-failure, open-failure, and release paths; the fixed-string call-site table is in `nfr-design-patterns.md` S1.
- Design Q6: `overlayWindowControllerProvider` is a hand-written `Provider` in `lib/src/providers/` with `ref.onDispose(controller.dispose)`; controller constructor = `(windowService, enumerator, {required handlerInstaller, required log})`; `CaptionOverlayTarget` constructor = `(controller, registry, DisplaySettings Function() displaySettings)` and reads the main buffer via `registry.activeTargets.whereType<OnScreenCaptionTarget>()`; the shell keeps its `_syncOverlay`/`ref.listen` machinery and gains an `events` subscription (`WindowClosed`/`OpenFailed` → write `overlayEnabled=false`; `DisplayLost` → `_overlayRegistered` bookkeeping only).
- Design Q7: `typedef OverlayMethodHandler`/`OverlayMethodHandlerInstaller` in `overlay_window_controller.dart`; the production const `overlayMethodHandlerInstaller` lives in `desktop_multi_window_service_io.dart` (wraps the static; `null` uninstalls), no-op const in the stub, both via the existing conditional export; installed once before the first `createWindow`, uninstalled only in `dispose()`; a `null` installer on a supported platform fails the open as `create_failed` before any `createWindow`.
- Design Q8: `({DisplayInfo? target, bool persistedIdPresent}) resolveOpenDisplay(List<DisplayInfo> displays, String? persistedId)` — pure, top-level in `overlay_window_controller.dart`, FP-4's direct subject; BR-U8-07 verbatim; "kept" is the absence of any write path, asserted by FP-4.
- Design Q9: `MockDesktopWindowService` needs no class change (mocktail covers the B-6 additions); new `FakeDisplayEnumerator` (scripted `displays()`, pushable broadcast `changes` replaying the latest list to late subscribers, idempotent `dispose`) and `FakeOverlayMethodHandlerInstaller`; six domain generators appended to `test/helpers/generators.dart`; FP-5 is a `_World` harness (real controller on fakes, real `CaptionBus`/registry, one `fakeAsync` per trial, a harness `overlayEnabled` flag modelling the shell's reaction) with the command set and per-command invariants fixed in `logical-components.md`.

## Rejected Patterns (with reason)
- Reset-timer debounce for `captionUpdate` (Phase 1 shape): never fires under a continuous stream shorter than the interval — violates the settled "regardless of the upstream rate" target.
- `SchedulerBinding.addPostFrameCallback` coalescing: not drivable by `fakeAsync` in the controller's unit tests.
- Per-call-site try/catch for the `'-1'`/ignored-error rules: four call sites, one rule — the same drift risk Unit 6's Rule 2 correction recorded.
- Per-window `changes` subscription ownership: T11 cannot fire from `WaitingForDisplay` and T4 needs the watch in `NoDisplays` — the FD event contract and D-4 contradict it.
- A pre-ready `'-1'` as an immediate `Failed`: invents a reason code outside BR-U8-03's fixed pair and contradicts B-5's "caught by the same timeout".
- A `@Riverpod`-generated notifier for the controller: the FD fixes a plain class; the project's service objects are hand-written `Provider`s.
- Source-grep redaction assertions: NFR Requirements Q6 chose record-level assertions (greps pass while a future edit regresses).
