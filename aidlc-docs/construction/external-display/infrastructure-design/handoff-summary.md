## Decisions Made
- ID-1: three-argument sub-window entry contract kept (`["multi_window", id, payload]`, verified in 0.2.1 on all three platforms); `main` gains one parameter; `overlayWindowMain` mirrors `GoogleFonts.config.allowRuntimeFetching = false` (B-4 — the overlay renders `CaptionDisplayWidget`, which calls `GoogleFonts.getFont`, zip_core `caption_display_widget.dart:72`); no Supabase, no root-logging in the sub-engine; malformed args → fixed "Window unavailable" frame (BR-U8-19).
- ID-2: one inbound message only — `captionUpdate` (JSON `CaptionOverlaySnapshot`); **no `popOutToggle`** (D-1); the sub-engine sends `overlayReady` to window 0 right after installing its handler (B-5); io-only `DesktopMultiWindow` via the existing conditional-export pair; the main engine has exactly one `setMethodHandler` owner, installed before the first `createWindow` (installer const in `desktop_multi_window_service_io.dart`, `null` uninstalls, uninstalled only in `dispose()`).
- ID-3: single-file `screen_retriever` import fence kept; re-query-and-diff `ScreenListener` contract (0.2.2 API: `addListener`/`onScreenEvent(String)`, no `displayChangedNotifier`); **`ScreenRetriever.instance` is not deprecated in 0.2.2** (`screen_retriever.dart:9`) — the old hazard paragraph is N/A under the `^0.2.2` pin, stated, no gamble; all three backends emit logical top-left (Windows divides `rcWork` by monitor scale in-plugin, `screen_retriever_windows_plugin.cpp:116-124`); Linux empty-`id` normalisation (`screen_retriever_linux_plugin.cc:76`); D-3 (work-area frame) recorded with its Backlog item.
- ID-4: close detection = ready handshake + error code; `overlayReadyTimeout` 10 s → `OpenFailed(ready_timeout)`; post-ready only `PlatformException` code `'-1'` = `WindowClosed` (identical code, verified: macOS `MultiWindowManager.swift:37`, Windows `multi_window_manager.cc:158`/`:163`, Linux `multi_window_manager.cc:83`/`:88`); anything else fixed-string logged + ignored; ping probe and D10 removed; `MissingPluginException` unreliable because pre-handler messages sit in the sub-engine's `ChannelBuffers` (capacity 1, `channel_buffers.dart:319`) and evictions answer null (`platform_channel.dart:351-364`).
- ID-5: borderless from the plugin's window-created callback in **all three runners**, no new dependency, no plugin patch; always-on-top dropped (not a Unit 8 requirement); `window_manager` gone (D-13). The callback also registers the sub-engine's plugins — **empty list for the locked set** (google_fonts 6.3.3 pure Dart; locked path_provider federations Dart-only PDM); macOS sub-window reachable via `controller.view.window` inside the callback (A7 item 3 — no `didBecomeKey` observer).
- B-1/B-2: `DisplayInfo.bounds` top-left logical everywhere; one pure `toPlatformFrame(Rect, TargetPlatform, {double? primaryFullHeight, double? displayScaleFactor}) → Rect` in `desktop_multi_window_service_io.dart` (NFR P5): macOS `cocoaY = primaryFullHeight − top − height` (primary height = `getPrimaryDisplay().size`), Windows multiply every edge by the target display's `scaleFactor` (0/missing → 1), Linux identity; unit-tested macOS-shaped / Windows-at-1.5x / mixed-DPI (FP-3, PBT-10 named examples).
- B-6: `DesktopWindowService` gains `setFrame(int id, Rect frame)` + `show(int id)` (conversion inside io only); open order `createWindow` → `setFrame` → `show` — the plugin never shows on create (verified all three backends); window renders standby until the first snapshot.

## Constraints
- No change outside the fence: the three runner files above, `lib/`/`test/`/`l10n/`, `pubspec.yaml` (`screen_retriever: ^0.2.2` + SECURITY-10 comment only), root `pubspec.lock` (exactly `screen_retriever` + four federated entries — anything else moving is reported, not committed silently), `macos/Podfile.lock` (only the `screen_retriever` pod entries the build adds). No CMake/manifest/Podfile/entitlement edits; no `window_manager`; no `zip_core` change.
- Windows runner code is compile-verified only by CI (`build-verify.yml` must be green); macOS compiles via `flutter build macos --debug` at Part 2. Placement, borderless rendering, hot-plug, OS-close, and sub-engine font rendering are Unit 9 manual checks — record, do not claim.
- The callback applies to every sub-window (fine for one kind; the pop-out unit needs a mode-aware variant — forward note only).
- BR-U8-18: fixed strings + error type at every new call site, including the native callback bodies (they set styles; no user data flows through them).
- Web stays excluded by `DesktopWindowService.isSupported`, never `kIsWeb`.
