## 0. Sign-in answer (the key question)

**Short answer: no. A broadcaster session cannot be obtained in the real desktop app against the local stack without an app change, a config change plus a Google client, or session injection. Every check that needs a signed-in broadcaster is marked NEEDS-JAMES.**

## 4. Blockers and contradictions

Blockers to Unit 9 runs (each needs James before it can run; none was changed):

- **B1. macOS entitlements lack `com.apple.security.network.client`** in both apps (`packages/zip_broadcast/macos/Runner/DebugProfile.entitlements` has only app-sandbox, allow-jit, network.server; `Release.entitlements` only app-sandbox; same in zip_captions; `git grep network.client develop -- packages` is empty). The sandboxed macOS app therefore cannot make outbound connections: Supabase (localhost:54321), STUN/TURN, WebRTC. Spike 2.1 hit the same and fixed only its throwaway app. Every macOS network check (EC1 to EC5, M1 to M5) fails until this is added. It is a native config change, not Dart app code, but it is a repo change and release-relevant. `keychain-access-groups` is also absent; `flutter_secure_storage` on macOS may fail with -34018 in the sandbox (unverified, needs a run).
- **B2. Anonymous viewers cannot get ICE servers.** `get_turn_credentials()` raises `42501` when `auth.uid() IS NULL` and is granted only to `authenticated` (`20261003000000_coturn_turn_credentials.sql:65,88`). The viewer calls it through `iceServersFor` (`viewer_session_notifier.dart:247-249`); a failure ends in `CannotConnect(IceFailed)` (line 253). `ENABLE_ANONYMOUS_USERS=false` and nothing calls `signInAnonymously`. The Unit 7 design says this is "anonymous-accessible". This likely fails exit criterion 1 ("viewer ... with no account") and is verifiable unattended with one RPC call using the anon key once the stack is up. Needs a decision (grant to anon, anonymous sign-in, or STUN-only fallback), which is design/security work in `zip_supabase` and pre-approval territory.
- **B3. Coturn local config blocks app-level relay tests.** `volumes/coturn/turnserver.conf` has `listening-ip=127.0.0.1` and `denied-peer-ip` for every private and loopback range, so relaying between two local endpoints is refused (403 Forbidden IP, by design, confirmed by Spike 2.3). The service uses `network_mode: host`, which Spike 2.3 found unreachable from other containers on Docker Desktop for Mac and possibly from the host apps (unverified; check `turnutils_stunclient`/the compose healthcheck first).
- **B4. No way to force relay in the app** (no `iceTransportPolicy`/relay-only option anywhere in `packages/*/lib`). EC3b needs a code change or a network where P2P really fails (James with a phone hotspot or a restricted network).
- **B5. Broadcaster sign-in unavailable on local stack** (section 0), and unavailable on Windows/Linux at all (Backlog).
- **B6. No real-protocol viewer swarm.** Capacity (EC5, M3) at the real cap of 50 needs 51 clients speaking the real Supabase signaling plus admission; the Spike 2.1 swarm uses a throwaway relay. Building one is a test-harness unit of work (the new harness would need `flutter_webrtc` native, so a Flutter app or `integration_test`, which no package depends on today).
- **B7. Accessibility** was never granted to the verifying host; A7 and B4 cannot be driven. `import Quartz` is not installed for `python3`, so `CGWindowListCopyWindowInfo` needs another route (a `swift` script, or James).
- **B8. Display-based checks need James's hands or eyes** (hot-plug, borderless on three OSes, font, opacity, theme, foreign full-screen). The Mac has two displays online right now (built-in plus 34UM95).
- **B9. Local stack migration state is unknown** until the DB container is started (section 2).
