Host-side microphone probes (ffmpeg -f avfoundation, macOS), run while the same
`say -r 120/150` phrases were being played that the app + spike were missing.

phys.wav      (device [1] "MacBook Pro Microphone")  mean_volume: -20.1 dB, max_volume: -0.7 dB
keepalive.wav (device [1] "MacBook Pro Microphone")  mean_volume: -22.4 dB, max_volume:  0.0 dB
blackhole.wav (device [0] "BlackHole 2ch", default)  mean_volume: -91.0 dB, max_volume: -91.0 dB (pure silence)

Interpretation: while the app/emulator received nothing, the Mac's physical
microphone clearly captured the played speech (-20 dB mean). The emulator's
host-mic capture stream (QEMU -> ranchu audio HAL TinyalsaSource) was in a
starved state (see emulator-hal-starvation.log: continuous
"pcm_readi failed with 'cannot read/write stream data: I/O error'"), so the
on-device recogniser was fed silence. When that stream is healthy (proven
multiple times), the app recognises and renders text correctly.
